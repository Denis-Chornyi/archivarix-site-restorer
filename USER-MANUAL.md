# Посібник користувача 773™ Site Restorer

## 1. Призначення

Програма відновлює статичну копію сайту з Internet Archive, збирає HTML, зображення, CSS, JavaScript, шрифти й залежності та створює нативний ZIP для Archivarix CMS.

Робота повністю алгоритмічна. Програма не використовує AI, не надсилає телеметрію та не зберігає паролі, Google-токени чи ключі.

## 2. Запуск

### Windows

1. Встановіть Node.js 18 або новіший.
2. Відкрийте `start.bat`.
3. Інтерфейс відкриється за адресою `http://127.0.0.1:4321`.

Ярлик `Archivarix Site Restorer.lnk` можна скопіювати на робочий стіл.

### macOS

```sh
chmod +x "773 Site Restorer.command"
```

Цю команду потрібно виконати лише один раз. Далі відкривайте `773 Site Restorer.command` подвійним кліком у Finder. Відкриється Terminal, а інтерфейс програми автоматично запуститься у стандартному браузері.

Якщо macOS заблокує перший запуск: натисніть файл правою кнопкою → **Відкрити** → **Відкрити**.

### Linux або запуск через Terminal

```sh
chmod +x start.sh
./start.sh
```

Альтернативний запуск на Windows, macOS і Linux:

```sh
npm start
```

## 3. Перше налаштування

Відкрийте вкладку **Налаштування**.

- **Папка для відновлених сайтів** — місце, де створюватимуться проєкти.
- **Стандартна повнота** — максимальний режим перевіряє найбільше альтернативних архівних дат.
- **Стандартний ліміт** — максимальна кількість ресурсів одного сайту.
- **Паралельні завантаження** — рекомендовано 2–3. Велике значення не прискорює Internet Archive і може збільшити кількість тимчасових відмов.
- **Локальний склад** — повторно використовує вже завантажені файли.
- **Версіоновані CDN** — дозволяє брати точну відому версію бібліотеки з cdnjs, jsDelivr або unpkg.

Після змін натисніть **Зберегти налаштування**.

## 4. Відновлення сайту

1. Відкрийте вкладку відновлення.
2. Введіть домен, наприклад `example.com`, або повне Wayback-посилання.
3. За потреби задайте період пошуку.
4. Оберіть архівну дату.
5. Натисніть кнопку початку відновлення.
6. Стежте за етапом, лічильниками та журналом у реальному часі.

Програма обробляє ресурси в такому порядку:

1. HTML;
2. зображення;
3. CSS;
4. JavaScript;
5. інші файли.

Для кожного ресурсу програма:

- робить початкову спробу і до п’яти повторів при мережевій помилці;
- чекає 1, 2, 4, 8 і 16 секунд між повторами;
- перевіряє кілька найближчих архівних дат;
- пробує `http://` і `https://`;
- перевіряє варіанти домену з `www` і без нього;
- використовує локальну бібліотеку та, за дозволом, точний версіонований CDN.

П’ять повторів є спільним бюджетом одного ресурсу, а не окремим бюджетом для кожного HTTP/HTTPS/www-варіанта. Якщо Internet Archive кілька разів поспіль повністю відмовляє, програма тимчасово відкриває circuit breaker: решта додаткових залежностей отримує `retry_later` без багатохвилинного очікування, а проєкт продовжує формуватися.

Помилка одного CSS або JavaScript не зупиняє решту процесу.

## 5. Статуси ресурсів

- **downloaded** — файл отримано з локального складу або дозволеного зовнішнього джерела.
- **archived** — файл успішно відновлено з Internet Archive.
- **retry_later** — Internet Archive був тимчасово недоступний. Це не означає, що файла немає.
- **not_archived** — Internet Archive відповів, але жодної архівної копії не знайдено.
- **reconstructable** — типовий ресурс CMS або фреймворку, який можна відновити з відповідної версії системи чи пакета.

Розпізнаються типові ресурси Joomla, WordPress, Drupal, Laravel/Vite, Magento, PrestaShop, OpenCart, TYPO3, Next.js і Nuxt. Наприклад:

- `/media/system/*`;
- `/templates/*`;
- `/components/com_phocagallery/assets/*`.
- `/wp-includes/*`, `/wp-admin/*` і стандартні assets плагінів/тем;
- `/core/assets/*`, `/core/misc/*`, `/modules/contrib/*`;
- `/build/assets/*`, `/_next/static/*`, `/_nuxt/*`;
- системні каталоги Magento, PrestaShop, OpenCart і TYPO3.

## 6. Результат і звіти

Кожен проєкт має структуру:

```text
<папка проєктів>/
└── example.com/
    └── 2024-08-13_16-26-11_123456/
        ├── site/
        ├── reports/
        │   ├── restore-manifest.json
        │   ├── recovery-report.txt
        │   ├── errors.json
        │   └── restore.log
        ├── packages/
        └── README.txt
```

`recovery-report.txt` згруповано за завантаженими, архівними, тимчасово недоступними, відсутніми та реконструйованими ресурсами.

## 7. Імпорт в Archivarix CMS

1. Відкрийте вкладку **Готові проєкти**.
2. За потреби натисніть **Відновити JS/CSS**.
3. Завантажте **Нативний ZIP Archivarix**.
4. В Archivarix CMS відкрийте імпорт сайтів.
5. Завантажте ZIP зі `structure.db`.
6. Після імпорту очистьте кеш сайту та браузера.

Не використовуйте ZIP експорту всього проєкту для імпорту в Archivarix — він призначений для перенесення між копіями програми.

## 8. Google Drive — спільна бібліотека до 10 ПК

### Підготовка

1. Створіть у Google Drive папку `773 Shared Library`.
2. Надайте доступ потрібним користувачам.
3. Встановіть Google Drive для комп’ютера. На Linux використайте клієнт, який показує Drive як локальну папку.
4. Дочекайтеся появи спільної папки на диску.

### Налаштування кожного ПК

1. Відкрийте **Налаштування → Google Drive — синхронізація бібліотеки**.
2. Натисніть **Обрати…** або введіть локальний шлях вручну.
3. Задайте зрозумілу назву ПК.
4. Оберіть напрям:
   - **Передавати й отримувати** — рекомендовано;
   - **Лише отримувати** — для комп’ютера без права публікації;
   - **Лише передавати** — для центрального збирача.
5. Оберіть синхронізацію при запуску, після відновлення або за інтервалом.
6. Натисніть **Перевірити підключення**.
7. Збережіть налаштування.

У вкладці **Бібліотека**:

- **Синхронізувати** — передати локальні й отримати чужі ресурси;
- **Отримати зміни** — лише завантажити ресурси інших користувачів;
- статус показує час, кількість переданих і отриманих файлів.

Кожен ПК записує окремий маніфест. Файли зберігаються за хешем, тому однакові CSS/JS не дублюються.

Під час кожного відновлення програма спочатку шукає ресурс у локальній і синхронізованій бібліотеці за архівним digest, точним URL та безпечною версійною сигнатурою CSS/JS. Звернення до Internet Archive виконується лише тоді, коли сумісного локального файла немає. Версійна сигнатура між різними доменами використовується тільки для відомих бібліотек/CMS або файлів із явною версією чи content hash, щоб не підставити несумісний `app.js` або `style.css`.

## 9. Типові проблеми

### `retry_later`

Internet Archive тимчасово не відповідав. Запустіть відновлення повторно пізніше. Не видаляйте локальну бібліотеку — успішно отримані файли будуть використані повторно.

### Сайт відкривається без CSS

1. Перегляньте `recovery-report.txt`.
2. Перевірте групи `retry_later` та `not_archived`.
3. Натисніть **Відновити JS/CSS** у готовому проєкті.
4. Повторно створіть та імпортуйте нативний ZIP.
5. Очистьте кеш Archivarix.

### Порожня сторінка після імпорту

- переконайтеся, що використано `*-archivarix-native-v4.zip`;
- перевірте наявність `structure.db`;
- перегляньте звіт пакета;
- повторно імпортуйте пакет після ремонту JS/CSS.

### Google Drive не синхронізується

- переконайтеся, що клієнт Google Drive запущений;
- перевірте права запису до спільної папки;
- зробіть папку доступною офлайн, якщо клієнт підтримує цей режим;
- натисніть **Перевірити підключення**;
- не вибирайте корінь диска, папку проєктів або локальний `asset-vault`.

## 10. Безпечне видалення

Видалення проєкту у вкладці **Готові проєкти** фізично видаляє його `site`, звіти та пакети. Спільна бібліотека ресурсів не видаляється.

Перед видаленням важливого проєкту скористайтеся **Експортом проєкту**.
