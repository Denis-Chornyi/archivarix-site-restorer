# 773™ Site Restorer for Archivarix

## Повний recovery pipeline

Для кожної невідновленої залежності програма послідовно перевіряє локальну
бібліотеку, прямий Wayback replay, HTTP/HTTPS і URL без query, CDX та сусідні
дати, альтернативні CMS-шляхи, те саме ім'я файла серед усіх снапшотів домену,
безпечний fuzzy-збіг, синхронізовану бібліотеку й довірений CDN. Остаточний
статус виставляється лише після завершення каскаду.

Профіль сайту визначається автоматично: Joomla, WordPress, Quick.Cart, Xara Web
Designer, OpenCart, PrestaShop або Generic HTML. Для Xara додатково перевіряються
корінь сайту, поточна папка та `index_htm_files`.

`reports/restore-manifest.json` містить відсоток відновлення, джерело кожного
файла, відсутні CSS/JS/зображення/шрифти, використані стратегії та точну причину
кожної невдачі.

773™ — локальна програма, що відновлює статичну копію сайту зі снапшотів Wayback Machine та створює ZIP, який можна імпортувати в Archivarix CMS.

Програма **не використовує AI**. Усі рішення приймаються відтворюваними алгоритмами: зіставленням URL і дат, аналізом HTML/CSS/JS та перевіркою локальних файлів.

## Запуск

- Windows: відкрийте `start.bat`.
- macOS: один раз виконайте `chmod +x "773 Site Restorer.command"`, після чого запускайте файл `773 Site Restorer.command` подвійним кліком у Finder.
- macOS/Linux у терміналі: `chmod +x start.sh && ./start.sh`.
- Або: `npm start`.

Потрібен Node.js 18 або новіший і доступ до `web.archive.org`. Інтерфейс відкривається на `http://127.0.0.1:4321`.

## Як користуватися

1. Введіть домен і натисніть **Знайти снапшоти**.
2. Оберіть дату збереженої головної сторінки.
3. Задайте ліміт файлів та почніть відновлення.
4. Результат з’явиться в `<папка з налаштувань>/<домен>/<дата-час>/`.
5. У вкладці **Готові проєкти** натисніть **Нативний ZIP Archivarix**.
6. Завантажте отриманий `*-archivarix-native.zip` у звичайний імпортер Archivarix CMS. Пакет містить `structure.db` і має розпізнаватися як повноцінний архів Archivarix.

Кнопка **Експорт проєкту** створює повну резервну копію з папками `site`, `reports` і `packages`. Вона призначена для перенесення між копіями цієї програми та не імпортується звичайним імпортером Archivarix CMS.

## Структура папок

```text
<папка з налаштувань>/
└── example.com/
    └── 2024-08-13_16-26-11_123456/
        ├── site/       готові файли сайту
        ├── reports/    restore-manifest.json і помилки
        ├── packages/   ZIP сайту та експорт проєкту
        └── README.txt
```

Старі проєкти з плоскою структурою продовжують відображатися й відкриватися.

## Керування

- **Готові проєкти** — відкриття папки, перегляд звіту й помилок, видалення результату.
- Проєкти можна експортувати в ZIP та імпортувати на іншому комп’ютері.
- **Бібліотека** — перегляд і видалення автоматично накопичених CSS/JS/шрифтів, експорт та імпорт спільного `asset-vault`.
- **Налаштування** — вибір папки збереження та стандартних параметрів відновлення.
- Ярлик `Archivarix Site Restorer.lnk` можна перетягнути або скопіювати на робочий стіл.
- Видалення проєкту не очищає спільний `asset-vault`, тому повторні відновлення залишаються швидкими.

## Що робить програма

- отримує список снапшотів через Internet Archive CDX API;
- знаходить ресурси домену, найближчі до обраної дати;
- у максимальному режимі перевіряє до семи архівних копій кожного ресурсу в діапазоні ±5 років;
- надає пріоритет CSS, JavaScript, HTML, шрифтам і зображенням, щоб ліміт не псував вигляд сайту;
- завантажує оригінальні відповіді через режим Wayback `id_`;
- відновлює структуру папок і локалізує `url()`, `@import`, `src`, `href`, `srcset` та абсолютні URL у JavaScript;
- розпізнає UTF-8, Windows-1251, Windows-1252 та інші кодування, підтримувані Node.js;
- формує `restore-manifest.json`, ZIP та текстову інструкцію.
- після завантаження перевіряє биті локальні залежності й окремо звітує про зовнішні ресурси.
- виконує автоматичний другий прохід по HTML/CSS/JS і дозавантажує реально використані залежності;
- зберігає точні архівні CSS, JS, шрифти, зображення та файли плагінів у `asset-vault`;
- повторно використовує ресурси за Wayback digest або точним URL;
- розпізнає jQuery, Bootstrap, WordPress core, Elementor, WooCommerce, Contact Form 7, Slider Revolution, Slick, Swiper, Font Awesome, Modernizr, Lodash, React, Vue та Angular;
- якщо архівні копії недоступні, може завантажити лише явно версіонований файл з `cdnjs`, `jsDelivr` або `unpkg`.

Програма навмисно не підставляє «останню» версію бібліотеки: сучасний jQuery або Bootstrap часто несумісний зі старим сайтом.

## Синхронізація бібліотеки між комп’ютерами

Синхронізація працює через локальну папку будь-якого файлового хмарного клієнта. Рекомендований варіант — Google Drive для комп’ютера:

1. Створіть у Google Drive папку, наприклад `773 Shared Library`, і надайте доступ потрібним користувачам.
2. Встановіть Google Drive для комп’ютера на Windows або macOS. На Linux можна використати клієнт, який монтує чи синхронізує Drive як звичайну папку.
3. У вкладці **Налаштування** вкажіть локальний шлях до цієї спільної папки.
4. За потреби увімкніть автоматичну синхронізацію після запуску та завершення відновлення.
5. У вкладці **Бібліотека** кнопка **Синхронізувати** передає локальні зміни й отримує чужі, а **Отримати зміни** нічого не публікує.

Кожен комп’ютер має окремий ідентифікатор і власний маніфест. CSS, JavaScript, шрифти та інші ресурси зберігаються за хешем у `773-asset-library-v1/objects`, тому однакові файли не дублюються, а одночасна робота до 10 користувачів не вимагає спільного API-ключа. Паролі та облікові дані Google програма не читає — доступом керує офіційний клієнт Google Drive.

Не розміщуйте в цій папці відновлені проєкти: вона призначена лише для спільної бібліотеки ресурсів.

У налаштуваннях також доступні системний вибір папки, назва ПК, перевірка доступу, напрям обміну, синхронізація при запуску, після відновлення та за часовим інтервалом. При копіюванні програми на інший комп’ютер ідентифікатор пристрою автоматично змінюється.

## Стійкість Internet Archive

- кожна мережева помилка Internet Archive отримує до п’яти повторів із паузами 1, 2, 4, 8 і 16 секунд;
- бюджет повторів спільний для всіх URL-варіантів одного ресурсу; circuit breaker не дозволяє масовій відмові Archive розтягнути другий прохід на години;
- перевіряються кілька найближчих дат, HTTP/HTTPS та адреси з `www` і без нього;
- мережеві збої мають статус `retry_later`, а не «файл відсутній»;
- підтверджена відсутність копії має статус `not_archived`;
- стандартні ресурси Joomla, WordPress, Drupal, Laravel/Vite, Magento, PrestaShop, OpenCart, TYPO3, Next.js і Nuxt мають статус `reconstructable`;
- підсумок записується у `reports/recovery-report.txt` і групується за результатом.

Повний покроковий посібник: `USER-MANUAL.md` або кнопка **Відкрити посібник** у вкладці налаштувань.

Перевірка після змін: `npm test`.

Archivarix — окремий сторонній продукт. Програма не використовує закриті API, не обходить оплату та не містить код Archivarix CMS.
